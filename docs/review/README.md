# "수정 요청" 위젯 — 구글 시트 저장소 설치 (담당: 강민아)

오픈 전 검토용 "수정 요청" 메뉴(`public/review/review.js`)가 올린 요청을 **구글 시트 한 장**에 모읍니다.
서버·DB 없이 시트에 붙은 Apps Script 를 "웹 앱"으로 배포하면 그 주소가 곧 API 입니다.

## 1. 시트 만들기 (한 번)

1. 구글 드라이브에서 새 **Google 스프레드시트**를 만듭니다. 이름은 자유(예: `구리 생활지도 수정요청`).
2. 메뉴 **확장 프로그램 → Apps Script** 를 엽니다.
3. 편집기의 `Code.gs` 내용을 지우고 이 폴더의 [`Code.gs`](./Code.gs) 내용을 그대로 붙여넣고 저장합니다.
   - 관리자 암호를 바꾸려면 맨 위 `ADMIN_KEY` 를 고치고, `review.js` 의 `ADMIN_VALUE` 도 같은 값으로 맞춥니다(기본 `guri`).
4. 오른쪽 위 **배포 → 새 배포** → 유형 선택(톱니) **웹 앱**
   - 설명: 아무거나
   - 실행 사용자: **나**
   - 액세스 권한: **모든 사용자**
   - **배포** → 처음이면 권한 승인(시트·드라이브 접근) → **웹 앱 URL** 복사 (`https://script.google.com/macros/s/…/exec`)
5. 브라우저에서 `웹앱URL?action=ping` 을 열어 `{"ok":true,...}` 가 보이면 됩니다.

## 2. review.js 에 주소 넣기

`public/review/review.js` 맨 위:

```js
var API = 'PASTE_APPS_SCRIPT_WEB_APP_URL';
```

여기에 4번의 웹 앱 URL 을 넣고 커밋·배포합니다. 주소가 비어 있으면 위젯의 목록 탭에 "API 주소가 아직 설정되지 않았어요"가 뜹니다.

## 3. 쓰는 법

- 요청은 시트의 `수정요청` 탭에 한 줄씩 쌓입니다(시트가 없으면 스크립트가 만듭니다). 캡처는 시트가 들어 있는 폴더(공유 드라이브 포함) 안의 `구리 생활지도 수정요청 캡처` 폴더에 저장되고 시트에는 파일 ID 만 적힙니다.
- 상태는 `status` 열입니다. 시트에서 `done`(또는 `수정완료`)으로 바꾸면 화면 목록에도 "수정완료"로 보입니다. 화면에서 바꾸려면 주소 뒤에 `?review=guri` 를 붙여 열면 "완료/되돌리기" 버튼이 생깁니다.
- 삭제는 본인이 올린 것(같은 브라우저) 또는 관리자만 됩니다. 시트에서 행을 지워도 됩니다.
- 엑셀이 필요하면 시트 메뉴 **파일 → 다운로드 → Microsoft Excel**.

## 4. Code.gs 를 고쳤을 때

Apps Script 는 **배포 → 배포 관리 → 편집(연필) → 버전: 새 버전 → 배포** 를 해야 웹 앱 URL 에 반영됩니다(URL 은 그대로).

## 5. 오픈할 때

각 페이지의 `<script src="/review/review.js" defer>` 한 줄(홈은 `src/app/layout.tsx` 의 `<Script …>`)만 지우면 화면에서 사라집니다. 시트와 스크립트는 남겨 둬도 됩니다.

## 동작 방식(참고)

| 호출                                      | 내용                                                                                   |
| ----------------------------------------- | -------------------------------------------------------------------------------------- |
| `GET ?action=list`                        | 전체 목록(최신 먼저), `status` 는 `todo`/`done` 으로 정규화                            |
| `GET ?action=shot&id=파일ID`              | 캡처를 `data:` URL 로 (스크립트가 소유자 권한으로 읽으므로 파일 공유 설정이 필요 없음) |
| `POST {action:'add', …}`                  | 한 줄 추가, 캡처는 드라이브 저장                                                       |
| `POST {action:'status', id, status, key}` | 관리자 암호가 맞을 때만 상태 변경                                                      |
| `POST {action:'delete', id, owner, key}`  | 본인 토큰 또는 관리자 암호                                                             |

브라우저에서 Apps Script 로 POST 할 때는 `Content-Type` 헤더를 붙이지 않습니다(붙이면 사전 요청이 생겨 막힙니다). `review.js` 가 이미 그렇게 되어 있습니다.
